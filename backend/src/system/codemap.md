# backend/src/system/

## Responsibility
Host-level operations beyond the array/Docker/LXC layers: system stats, service control, log queries, hostname/timezone/reboot, disk spin control, CPU temp, disk type, I/O benchmarks, array data-directory provisioning, array lifecycle orchestration, and config backup/restore.

## Design
- **`SystemStatsService`** (service.ts): an unref'd interval worker (config.systemStatsIntervalMs) sampling `os.cpus()` twice to compute CPU%. `getStats()` builds `SystemStats` purely from the `os` module (hostname/timezone/uptime/mem/`networkInterfaces`, with `docker0`/`lxcbr0` excluded) plus `readCpuTempCelsius()`, the build-time `BUILD_HASH`/`VERSION`, and a cached `BootDiskInfo` (identity resolved once via df+lsblk; capacity/temp refreshed on a 60s interval through `SmartService`).
- **`procUtil.ts`**: the root-run helper trio — `spawnMaybeSudo` (stdio ignore/pipe/pipe), `spawnWithPipedStdin` (for piped openssl/tar), and `runSudoMaybe` (collects output, throws `Error(stderr || "exited with code N")`).
- **`services.ts`**: static `SERVICE_DEFS` (docker/lxc/smb/nfs/ssh/avahi/tailscale/rclone-rcd); `getServiceState` runs `systemctl is-active` over `statusUnits` → active/inactive/failed/mixed; start/stop/restart via systemctl, with restart as an explicit stop-then-start.
- **`logs.ts`**: `LOG_SOURCE_DEFS` (journalctl selector args), `WINDOW_DEFS`, `clampTail`, and `queryLog` building `journalctl --no-pager -q -o short-iso` with `--since @cursor` (live tail) or a window + `-n tail`; `nextSinceFromLogText` mirrors docker/realClient.ts's cursor logic.
- **Small tools**: `hostConfig.ts` (validated `hostnamectl set-hostname`, `timedatectl` timezone list/set, `systemctl reboot`), `hdparm.ts` (spinDown via `hdparm -y`; spinUp via a `dd iflag=direct` single-sector read since `-C` can't force a spin-up), `cpuTemp.ts` (hwmon sysfs scan for coretemp/k10temp/zenpower/cpu_thermal, preferred labels), `diskType.ts` (`lsblk ROTA` → SSD/HDD, preferred over smartctl's rotation_rate).
- **`benchmark.ts`**: `benchmarkRead` spawns `dd iflag=direct` (O_DIRECT can't be done portably from JS) and SIGUSR1-polls GNU dd every 250ms for instantaneous samples, time-bounded with a `MAX_MB` ceiling; `benchmarkWrite` writes a throwaway file through the mount with per-chunk `datasync`; `resolveDurationMs` clamps client input; one system-wide `withLock`.
- **`arrayDir.ts`**: `provisionArrayDir` — mkdir, chown to `arrayDataOwner:Group` (user:users 99:100), `find -type d -exec chmod g+s`, and a recursive+default `setfacl` so everything created under the dir by Samba/NFS/containers stays group-accessible.
- **`arrayLifecycle.ts`**: shared array bring-down/bring-up helpers — `unmountArrayWithContainerRetry` (unmount, then on failure stop docker + running LXC + `shares.unmountAll()`, retry), `restoreStoppedContainers`, `restoreDockerAndAutostartLxc`, and `mountArrayDisksBestEffort` (mountDisks + `warnUnmountedDataDisks` + shares.remountAll). Callers compose with their own share-unmount strictness.
- **Backup subsystem**: `backupCatalog.ts` (category list is the single source of truth; `resolveConfigBackupPaths`/`resolveExistingCategoryIds`), `backupMeta.ts` (plaintext `.meta.json` sidecar; missing sidecar reads as legacy-unencrypted), `backupCrypto.ts` (openssl enc AES-256-CBC+pbkdf2 via piped spawn, password in a 0600 single-use temp file, never argv; `PasswordRequiredError`/`IncorrectPasswordError`), `backupStream.ts` (streaming tar/dd to an HTTP response or a file, optional inline openssl enc pipe for encryption), `backupScheduler.ts` (weekly/monthly ticker + `runNow` + `prune` + `listBackups`), `configRestore.ts` (TTL-swept staged uploads, `tar -tzf` listing, member-selective extraction to `/`, `decryptIfNeeded`, `buildRestorePreview`).

## Flow
- routes/system.ts → `SystemStatsService.getStats` / logs / services / hostConfig / hdparm / benchmark / backup endpoints.
- Backup: `BackupScheduler.tick` (`scheduleMatches` + `lastFiredKey`) → `runNow` → `resolveBackupDestDir` → `resolveConfigBackupPaths` → `writeConfigBackupToFile` (optionally encrypted) → `writeMetaSidecar` → prune. Restore: upload/local/remote → `decryptIfNeeded` → `buildRestorePreview` → `restoreArchiveMembers`, plus an nmd superblock reload when the array is blank.
- Array lifecycle: /array/stop → `shares.unmountAll` → `unmountArrayWithContainerRetry` → `nmd.stopArray`; /array/start → `nmd.startArray` → `mountArrayDisksBestEffort` → `restoreDockerAndAutostartLxc`.

## Integration
- Consumed by routes/system.ts, routes/array.ts, routes/disks.ts (disk-queue flow), routes/services.ts, routes/logs.ts, routes/status.ts, routes/settings.ts, routes/smart.ts; `BackupScheduler` is constructed in index.ts with nmd/settingsStore/activity/metrics/rclone; `MetricsSampler` drives `SystemStatsService`.
- Depends on nmd (status, superblock path), smart (`SmartService` for boot-disk temp), cache (docker/lxc storage migrations), docker (`DAEMON_JSON_PATH` in backupCatalog), and config across the board.
